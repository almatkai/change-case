# Change Case — Rust Native V2

A standalone offline Rust library and a concrete production adapter for the pinned Tezbar Native V2 beta. All **22 commands** are declared and dispatched: interactive Change Case plus all 21 direct converters. Original V1 remains available and unchanged. Source base: `b33e675ea3945e08f87dc5ffc8428f5b7dc9d12c`; beta API: `fd300e276356587726566026f072563eb9c34cb1`.

The runtime uses Rust only. JavaScript, TypeScript, Node and npm are validation tools, not runtime dependencies. The unchanged original icon and author/contributor credits are described in [NOTICES.md](NOTICES.md). See [INTEGRATION.md](INTEGRATION.md) for required compiled host integration and [VALIDATION.md](VALIDATION.md) for reproducible tests and gaps.

`Cargo.toml` targets Rust 1.85+, with locked exact direct dependencies. `src/lib.rs` exposes `CASES`, `COMMANDS`, `convert`, `modify`, and deterministic `*_with` random-tape variants; `adapter.rs` exposes `commands` and the concrete beta `handle` signature. `manifest.json` is schema 2, canonical `com.tezbar.native.change-case`, replacing `raycast.change-case`. Both macOS and Windows verification intentionally remain **not-run**.

The engine preserves own-source behavior including prefix/suffix characters, acronym/digit boundaries, pre-lowercase exemptions, case-preserving punctuation (including Capital Case), title-case small words/exceptions, contextual Greek sigma, ECMAScript UTF-16 indexing, and per-BMP-letter random/alternating behavior. Randomness uses OS entropy in production and a deterministic tape only in oracle tests. Direct converters process lines independently; immediate launch-context conversion applies the function to the entire input exactly as the own source does.

The interactive adapter preserves pinned/recent/all ordering, case enable preferences, source priority, fallback text, aliases, copy/paste preference order, pin/unpin/clear/remove actions and refresh. Only pinned/recent case names persist, in Native V2 SDK storage. Unknown keys survive process-atomic updates, malformed storage is rejected, and no unknown legacy cache is migrated. History is capped at four plus the pinned count, as in V1. Search runs on the server, so beta client filtering cannot reorder or hide computed results. No new text-entry form is invented: V1 has no such form.

Limits are explicit errors, never truncation: **65536 UTF-8 input bytes**, **524288 UTF-8 output bytes**, **4096 UTF-8 search bytes**, and at most **21 distinct valid case names** in either history array. Conversion preferences use the original manifest defaults. Casing tables deliberately match the oracle's default **en-US** locale and Unicode 17; OS-specific Turkish/Azeri/Lithuanian default-locale behavior has not been implemented or claimed. Non-BMP letters remain unchanged where the source indexes UTF-16 code units; scalar-based swap and word splitting still recognize them.

Pinned beta limitations are explicit: quicklink creation has no host API and the retained action reports an error; supplied `launchContext.case` is handled only if a caller forwards it (the current typed launcher request cannot create quicklinks). There is no real HUD/toast API: successful conversions use the native result message, suppressed by `hideHUD`; failures/recovery appear inline. The active app's name/icon cannot be queried through this beta SDK, so paste is labeled “Paste in Active App.” Both source close/pop outcomes map to the beta no-view result and copy hide route. Arbitrary Raycast shortcuts, per-action icons, selected-recent initial row behavior, and exact Raycast detail styling are not supported by the beta renderer. Real UI behavior needs QA.

Every copy/paste/hide effect requires an object with `ok:true`, no non-null `error`, and absent or true `success`. Failed/malformed/transport outcomes never claim success. Interrupted or uncertain effects require an explicit retry action; acknowledged paste/copy is not repeated when storage or hiding later fails. Output is resolved from committed session bindings, never event-supplied text/URLs. Stale/forged/cross-session/discarded-search IDs fail without consuming valid bindings; refresh returns unchanged and cannot create capabilities from a discarded clone.
